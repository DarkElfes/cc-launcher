# cc-launcher

A Windows desktop app built around projects for working with Claude Code across several of the
owner's own Claude accounts. Projects keep their state in the repo. Accounts are "profiles", each
with its own `CLAUDE_CONFIG_DIR`. The app runs the official `claude.exe` in embedded terminals.

Plan: `docs/PLAN.md`. Current state: `docs/STATUS.md`. **Update STATUS.md at the end of every session.**

## Commands (pnpm, not npm)

| Command | What it does |
| --- | --- |
| `pnpm install` | install deps (run `pnpm exec install-electron` if `node_modules/electron/dist` is missing) |
| `pnpm dev` | run with hot reload |
| `pnpm build` | build to `out/` |
| `pnpm start` | run the built app |
| `pnpm typecheck` | `tsc --noEmit` over all of `src/` |
| `pnpm dist` | build the Windows installer → `dist/cc-launcher-Setup-<version>.exe` (no upload) |
| `pnpm release` | build and upload to the `publish` target in `electron-builder.yml` (for auto-update) |
| `pnpm dlx shadcn@latest add <name>` | add a shadcn component to `src/renderer/src/components/ui/` |

Releasing: see `docs/RELEASING.md`. **The repo is public**, and updates come from its GitHub releases
without a token. Never commit secrets: tokens, `.credentials.json`, `.claude.json`, profile folders.

## Architecture

```
src/
  shared/types.ts      types shared by every process, including the preload `Api` contract
  main/                Electron main process (Node)
    index.ts           window, IPC handlers, resolving where claude.exe is
    store.ts           %APPDATA%\cc-launcher\app.json (projects + settings, never credentials)
    profiles.ts        profile folders (~/.claude-profiles/<name>, "default" = ~/.claude), env for claude
    terminals.ts       node-pty processes keyed by id
    updater.ts         electron-updater wrapper (only active in installed builds with a publish target)
    usage.ts           per-profile status-line script that records rate_limits (5h/weekly usage)
  preload/index.ts     contextBridge → window.api (the only renderer↔main surface)
  renderer/            React UI
    src/App.tsx        shell (shadcn Sidebar), view routing, terminal tabs, update toast
    src/views.tsx      Dashboard, ProjectView, AccountsView, SettingsView
    src/TerminalPane.tsx  xterm.js bound to one pty; stays mounted while hidden
    src/termBus.ts     routes pty output to terminals, buffering until they mount
    src/components/ui/ shadcn components (generated by the CLI; edit sparingly)
    src/components/confirm.tsx  promise-based AlertDialog: `await confirm({...})`
    src/index.css      Tailwind v4 + shadcn theme tokens (dark only)
electron-builder.yml   NSIS installer + publish target for auto-update
vite.config.ts         only for the shadcn CLI; the build uses electron.vite.config.ts
```

Stack: Electron + electron-vite, React 19, TypeScript, Tailwind v4, shadcn/ui (**style: radix-lyra**,
Phosphor icons, JetBrains Mono), sonner toasts, `@xterm/xterm`, `@lydell/node-pty` (prebuilt N-API,
so it needs no native rebuild), electron-builder, and electron-updater.

## Conventions

- IPC: `invoke` handlers return `Result<T>` (`{ok, value}` / `{ok:false, error}`) and never throw
  to the renderer. Channel names look like `area:action`.
- Every new IPC call goes into `Api` in `shared/types.ts` first, then into the preload and the main process.
- The renderer is sandboxed (`contextIsolation`, `sandbox`, no node). Keep Node APIs in `main/`.
- Profile names: `^[a-z0-9][a-z0-9_-]{0,31}$`. Profiles live only in `~/.claude-profiles/<name>`.
  Never use the shared `~/.claude` folder as a profile.
- Window: frameless with a native controls overlay. Title bar areas use `.app-drag`, and right-side
  content uses `.titlebar-safe`. Keep `TITLEBAR_HEIGHT` (main) equal to the title bar's `h-10`.
- Icon: edit `build/icon.svg`, then `pnpm icon`.
- UI: build from shadcn components and Tailwind classes. Don't write custom CSS files. Use theme
  tokens (`bg-background`, `text-muted-foreground`, …), not hard-coded colors. Profile colors from
  `profileColor()` are the one exception. Errors go to `showError()` (a toast). Confirmations use `useConfirm()`.
- Dependencies: only packages the main process loads at runtime go in `dependencies`
  (they ship in the installer). Everything bundled by Vite goes in `devDependencies`.

## Hard rules

- Only the owner's own accounts. No sharing, no selling access.
- **Never read, copy, log or send credentials.** The app may only check whether
  `<profile>/.credentials.json` exists. Login happens inside the official `claude` CLI.
- Launch only the official `claude` executable. Don't call Claude APIs directly.
- Session transcripts (`<profile>/projects/...jsonl`) use an internal format that can change.
  Read them defensively and only for display.
